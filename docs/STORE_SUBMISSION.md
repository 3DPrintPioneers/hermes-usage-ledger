# Store submission checklist

This document tracks the work required before submitting Usage Ledger to
Hermes plugin discovery. It deliberately contains no repository URL or commit
SHA until the public repository exists.

## Package identity

- Name: `usage-ledger`
- Current package version: `0.4.3`
- Release scope: Windows Desktop beta; live macOS/Linux support is unverified.
- Maintainer: `3DPrintPioneers`
- Repository: https://github.com/3DPrintPioneers/hermes-usage-ledger
- Hermes requirement: `>=0.21.5`.
- Package type: unified Hermes plugin with Python hooks, a scoped dashboard API,
  and a native Desktop statusline contribution.
- Runtime dependencies: none beyond Hermes and the Desktop plugin SDK.
- External credentials: none.
- External telemetry or provider calls: none.

## Before submission

- [ ] Create a public standalone Git repository.
- [ ] Add the repository URL and maintainer identity to the public metadata.
- [ ] Review the complete tracked tree for secrets, databases, caches, and
      generated bytecode.
- [ ] Run the CI workflow on Ubuntu, Windows, and macOS.
- [ ] Run `hermes plugins doctor . --ci` from a clean checkout.
- [ ] Test installation into a temporary `HERMES_HOME` from the released
      commit.
- [ ] Verify the Python backend and Desktop renderer activation gates
      separately.
- [ ] Verify the Usage popover, statusline selection, `Refresh now`,
      diagnostics, confirmation-protected clear, and restart/reopen behavior.
- [ ] Verify disable, update, and uninstall preserve local data.
- [ ] Create a real release and tag matching the package version.
- [ ] Record the exact 40-character commit SHA that will be submitted.

## Current Hermes distribution route

The current route is a maintainer-reviewed pull request adding
`plugin-catalog/usage-ledger.yaml` to
[NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent).
The former separate `hermes-plugin-index` repository no longer resolves.

Follow the current [catalog submission guide](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins/catalog-submission)
and [catalog schema](https://github.com/NousResearch/hermes-agent/blob/main/plugin-catalog/README.md).
Use the full 40-character release SHA, `tier: community`, `category: desktop`,
`platforms: [windows]`, truthful version/Hermes requirement, repository and
documentation URLs, and the four declared observer hooks. Opening a PR is not
catalog admission; maintainers must review and merge it.

The admission scanner currently flags `inline_shell_exec` at the literal
response-text regular expression in `tally_writer.py`. Disclose that caution
for review: it counts fenced text and does not execute shell commands. Do not
represent a caution as an unqualified clean scan.

## Trust disclosure

The public listing must explain that enabling the plugin executes Python hooks
in-process. It must also explain that the plugin stores only numeric tally
state and content-free opaque request metadata locally, never stores prompt or
response content, does not make external telemetry calls, and requires
confirmation before clearing observed-request rows.
